# Architecture Decision Records

Use ADRs for decisions that materially affect architecture, data ownership, API contracts, security boundaries, deployment, or major product mechanics.

## Naming

Use:

`NNNN-short-decision-name.md`

Example:

`0001-feed-pagination-strategy.md`

## Required sections

- Status
- Context
- Decision
- Alternatives considered
- Consequences
- Validation / follow-up

## Rules

- Do not create an ADR for trivial implementation details.
- Search existing ADRs before creating a new one.
- Update an existing ADR when the same decision is being revised rather than creating duplicates.
- Use `SUPERSEDED` when a decision is replaced.
